# S21 CSV Place Import Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Import Google Sheets CSV as place drafts through an admin three-step flow and provide a downloadable sample using the current place schema.

**Architecture:** Shared contracts parse CSV and validate mapped rows with PlaceEditInput and existing hours/phone/coordinate utilities. A places service previews exact and suspected duplicates and rechecks selected rows before insert-only writes. Persistent import identity keys and a unique MongoDB multikey index make CSV retries/concurrent imports safe. Admin uploads text through the shared API client and downloads a static UTF-8 CSV example.

**Tech Stack:** Existing TypeScript, Zod 4, NestJS, Mongoose, Vue 3, Vitest; no new dependencies.

**Spec:** docs/backlog.md S21; docs/data-collection.md §5; docs/ui-spec.md §12; current packages/contracts/src/place-admin.ts and enums.ts.

## Global Constraints

- Vietnamese user-facing copy, English identifiers, strict TypeScript, no any or ts-ignore.
- Import always creates draft/source admin; verifySource owner for Đã xác nhận/Sẵn sàng đăng, admin for Đăng chưa xác nhận.
- Only eligible status and imported != yes; current six categories and limits take priority over older documentation.
- Preserve unrelated existing working changes. Git metadata is read-only in this sandbox; implement in this checkout without commits or branch changes.
- Coordinate storage [lng, lat], use existing parseOpeningHours, keep public routes stable.
- Sample rows explicitly fictional; no real place facts or photos; CSV max 256 KiB and 500 data rows.

## Review Focus

- CSV quotes, BOM, CRLF, multiline notes, malformed headers/width must never shift data silently (Task 1 tests).
- Missing coordinates/hours remain valid drafts; supplied invalid/overlapping hours must be actionable errors (Task 1 tests).
- Exact identifiers in hidden/merged places and identities retained after edits must still block recreation (Task 2 tests).
- Ready rows that become suspected duplicates after preview must return for review; never trust client-provided draft data (Task 2 tests).
- Lost responses/expired sessions must retain file text and choices for a safe retry, and late responses must not replace a newer file (Task 3 tests).
